# ADR-0081: i18n — Primitives + Locale Routing

- Status: Public summary (the full decision record lives in the internal log)
- Date: 2026-10-19

## Context

A full i18n stack usually means a module or a routing convention. Ramonyx needed routing and
translation helpers without adding dependencies, and without surprising redirects that hurt SEO.

## Decision

1. Edge-safe primitives live in core: `parseAcceptLanguage`, `negotiateLocale`, `localePath`,
   `createTranslator` (interpolation, `Intl.PluralRules`, number/date formatting).
2. `createPageRoutes({ i18n })` registers routes **per locale** with literal prefixes
   (`/id/tentang`), not a dynamic `[locale]` segment — avoiding precedence conflicts with static
   routes and catch-alls.
3. The default locale is unprefixed by default; prefixed default URLs normalize with a `308`.
4. Locale reaches loaders, actions, page props, and the hydration payload; the document gets
   `<html lang>`/`dir` and automatic `hreflang` alternates.
5. Cache keys include the locale, so revalidated pages cannot leak data across languages.
6. No automatic detection/redirect: the helper is available for middleware + cookie flows, which
   keeps behavior explicit and cache-friendly.

## Consequences

- Apps opt in; without `i18n` behavior is unchanged.
- The route table grows linearly with locales.
- No ICU MessageFormat; formatting is `Intl`-based.
