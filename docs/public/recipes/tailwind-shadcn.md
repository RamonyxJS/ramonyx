# Add Tailwind CSS and shadcn/ui

shadcn/ui is not a component package. It is a set of source files copied into the app, built on
Tailwind utilities, `class-variance-authority`, `clsx`, and `tailwind-merge`.

Ramonyx does not currently inject CSS assets into the document, so this recipe compiles Tailwind to
a string at build time and injects it once from the root layout. That keeps SSR and hydration using
exactly the same CSS. The trade-off is that the CSS string is bundled into the client entry; for a
large design system, add a CSS asset/link pipeline later.

## Install

```bash
pnpm add -D tailwindcss @tailwindcss/postcss postcss
pnpm add class-variance-authority clsx tailwind-merge @radix-ui/react-slot
```

Tailwind/PostCSS are build-time dependencies; CVA, `clsx`, `tailwind-merge`, and Radix Slot are
runtime dependencies because copied shadcn components import them.

## Tailwind source

```css
/* src/styles.css */
@import "tailwindcss";
@source "./routes";
@source "./components";

@custom-variant dark (&:where([data-theme="dark"], [data-theme="dark"] *));

:root {
  --background: #ffffff;
  --foreground: #14160f;
  --primary: #2340c8;
  --primary-foreground: #f7f5ee;
  --destructive: #dc2626;
  --accent: #f3f1e8;
  --border: #d7d3c5;
  --ring: #2340c8;
}

@theme inline {
  --color-background: var(--background);
  --color-foreground: var(--foreground);
  --color-primary: var(--primary);
  --color-primary-foreground: var(--primary-foreground);
  --color-destructive: var(--destructive);
  --color-accent: var(--accent);
  --color-border: var(--border);
  --color-ring: var(--ring);
  --radius-md: 0.5rem;
}

* {
  border-color: var(--color-border);
}

body {
  margin: 0;
  background: var(--color-background);
  color: var(--color-foreground);
}
```

`@source` paths are relative to this CSS file. Tailwind only generates utilities for class names it
can find statically; dynamic string concatenation like `` `bg-${color}-500` `` is not detected. Use
CVA variants or safelist the names explicitly.

## Generated CSS module

```js
// scripts/build-tailwind.mjs
import { readFile, writeFile } from "node:fs/promises";
import { join } from "node:path";
import { fileURLToPath } from "node:url";
import tailwindcss from "@tailwindcss/postcss";
import postcss from "postcss";

const root = fileURLToPath(new URL("../", import.meta.url));
const inputPath = join(root, "src/styles.css");
const outputPath = join(root, "src/tailwind.generated.ts");

const input = await readFile(inputPath, "utf8");
const result = await postcss([tailwindcss()]).process(input, { from: inputPath });
await writeFile(
  outputPath,
  `// generated by scripts/build-tailwind.mjs — do not edit\nexport const TAILWIND_CSS = ${JSON.stringify(result.css)};\n`,
);
console.log(`tailwind: ${Buffer.byteLength(result.css)} bytes -> ${outputPath}`);
```

```json
// package.json (scripts)
{
  "css": "node scripts/build-tailwind.mjs",
  "dev": "pnpm css && ramonyx dev",
  "build": "pnpm css && ramonyx build"
}
```

Run `pnpm css` after changing classes or theme tokens. Commit `src/tailwind.generated.ts` or generate
it in CI before `build`; do not edit it by hand.

## Utilities

```ts
// src/lib/utils.ts
import { clsx, type ClassValue } from "clsx";
import { twMerge } from "tailwind-merge";

export function cn(...inputs: ClassValue[]): string {
  return twMerge(clsx(inputs));
}
```

## Button

This is the shadcn/ui Button pattern with relative imports (no `@/` alias required):

```tsx
// src/components/ui/button.tsx
import { Slot } from "@radix-ui/react-slot";
import { cva, type VariantProps } from "class-variance-authority";
import type { ComponentProps } from "react";
import { cn } from "../../lib/utils.ts";

const buttonVariants = cva(
  "inline-flex items-center justify-center gap-2 whitespace-nowrap rounded-md text-sm font-medium transition-colors focus-visible:outline-none focus-visible:ring-2 focus-visible:ring-ring disabled:pointer-events-none disabled:opacity-50",
  {
    variants: {
      variant: {
        default: "bg-primary text-primary-foreground hover:bg-primary/90",
        destructive: "bg-destructive text-white hover:bg-destructive/90",
        outline: "border border-border bg-background hover:bg-accent",
      },
      size: {
        default: "h-9 px-4 py-2",
        sm: "h-8 rounded-md px-3",
        lg: "h-10 rounded-md px-6",
      },
    },
    defaultVariants: { variant: "default", size: "default" },
  },
);

export interface ButtonProps
  extends ComponentProps<"button">,
    VariantProps<typeof buttonVariants> {
  readonly asChild?: boolean;
}

export function Button({
  className,
  variant,
  size,
  asChild = false,
  ...props
}: ButtonProps) {
  const Comp = asChild ? Slot : "button";
  return <Comp className={cn(buttonVariants({ variant, size, className }))} {...props} />;
}
```

`asChild` lets the same styles wrap an `<a>` or another interactive element without nesting buttons.
The `cn()` helper ensures a caller's `className` can override variant utilities predictably.

## Inject CSS

```tsx
// src/routes/layout.tsx
import type { LayoutProps } from "@ramonyx/react";
import { TAILWIND_CSS } from "../tailwind.generated.ts";

export default function RootLayout({ children }: LayoutProps) {
  return (
    <>
      <style>{TAILWIND_CSS}</style>
      <main className="mx-auto max-w-3xl p-6">{children}</main>
    </>
  );
}
```

The layout is rendered on the server and included in the hydration tree, so the generated CSS is
present before first paint and survives client navigation. The default CSP allows inline styles
(`style-src 'unsafe-inline'`); if you tighten CSP, add a nonce/styles hash policy or move this to a
custom document/stylesheet pipeline.

```tsx
// src/routes/page.tsx
import { Button } from "../components/ui/button.tsx";

export default function Page() {
  return (
    <section>
      <h1 className="text-2xl font-semibold tracking-tight">Akun</h1>
      <Button variant="destructive" size="sm">Hapus akun</Button>
    </section>
  );
}
```


The executable example [`tests/integrations/tailwind-shadcn.test.tsx`](../../../tests/integrations/tailwind-shadcn.test.tsx)

## Limits

- This recipe injects a **single global stylesheet**. It does not do per-route CSS splitting or
  remove unused CSS beyond Tailwind's scanner.
- `src/tailwind.generated.ts` contains the CSS as a JavaScript string. Large themes increase the
  client bundle; a dedicated CSS asset pipeline is the next step for large apps.
- shadcn/ui components are copied source, not a versioned package. Review upgrades and keep
  `components.json`/CLI aliases aligned if you use the CLI.
- Tailwind scans source text; class names built dynamically at runtime are invisible to it.
- Keep component code client-safe. Do not import `*.server.ts`, `node:*`, or secrets from
  `src/components/**`; Ramonyx's client-boundary lint still applies.
- If you use `@/` imports from the shadcn CLI, add a matching TypeScript path and a bundler alias;
  relative imports avoid that configuration in this recipe.
