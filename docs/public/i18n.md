# Internationalization

Locale routing and translation helpers are built in — no module, no dependency. Enable routing,
translate in loaders/components, and let the framework handle `<html lang>`, `hreflang`, and
per-locale caching.

## Enable locale routing

```ts
// src/app.ts
createPageRoutes({
  pages,
  renderer: createReactRenderer(),
  i18n: {
    locales: ["en", "id"],
    defaultLocale: "en",
    // prefixDefaultLocale: true,     // every locale gets a prefix (incl. default)
    // directions: { ar: "rtl" },     // <html dir="rtl"> for specific locales
  },
});
```

| Request | Result |
| --- | --- |
| `/about` | Served as the **default** locale (no prefix) |
| `/id/about` | Served as `id` |
| `/en` · `/en/about` | **308** → `/` · `/about` (when the default locale is unprefixed) |
| `prefixDefaultLocale: true` | The inverse: `/about` → 308 `/en/about` |

The framework also:

- sets `<html lang="…">` (and `dir` when configured);
- emits `<link rel="alternate" hreflang="…">` for every locale plus `x-default`;
- passes `locale` to loaders, actions, page props (`PageProps.locale`), and the hydration payload;
- **includes the locale in loader cache keys**, so revalidated pages cannot leak data across
  languages;
- leaves API routes untouched.

## Translating

Catalogs are plain nested objects (JSON-friendly). Load them where the data lives and pass them to
`createTranslator`:

```tsx
import { createTranslator, type Messages } from "ramonyx";

const catalog: Record<string, Messages> = {
  en: { hello: "Hello {name}!", items: { one: "{count} item", other: "{count} items" } },
  id: { hello: "Halo {name}!", items: { one: "{count} item", other: "{count} item" } },
};

export async function loader({ locale }: { locale?: string }) {
  const active = locale ?? "en";
  const { t, formatNumber, formatDate } = createTranslator({
    locale: active,
    messages: catalog[active] ?? {},
    fallbackMessages: catalog.en,        // optional
    // onMissing: (key) => console.warn("i18n:", key),
  });
  return {
    greeting: t("hello", { name: "Rina" }),
    count: t("items", { count: 3 }),      // plural via Intl.PluralRules
    price: formatNumber(1234.5),
    date: formatDate(new Date(), { dateStyle: "long" }),
  };
}
```

- **Interpolation**: `{name}` is replaced from the params object; unknown params stay as written.
- **ICU**: string messages support plural/selectordinal, select, number/percent/currency, and
  date/time (`{count, plural, one {# item} other {# items}}`). `formatMessage()` is exported for
  messages outside a catalog.
- **Plural objects**: object values (`one`/`other`/…) remain supported and use
  `Intl.PluralRules` with `params.count`.
- **Fallback**: missing key → `fallbackMessages` → `onMissing(key)` → the key itself.
- The helper is pure and edge-safe; it can also be used in middleware or client components.

The ICU implementation is a documented subset: no custom tag/style formatters, offsets, or
`{arg, spellout}`; malformed templates are returned unchanged instead of throwing.

## Language switcher

```tsx
import { localePath } from "ramonyx";

// From any page, build the same page in another locale (existing prefix is stripped).
<a href={localePath(currentPath, "id", { locales: ["en", "id"], defaultLocale: "en" })}>
  Bahasa Indonesia
</a>
```

## `Accept-Language` negotiation (middleware)

Use `localeDetection()` when you want automatic redirects. It checks the `locale` cookie first,
then `Accept-Language`, then the default; by default it only acts on `/` so cached pages and SEO
are not surprised. `strategy: "all"` extends it to other paths, and `/api`, `/assets`, `/_`, and
`/__ramonyx` are skipped.

```ts
import { localeDetection } from "ramonyx";

export const middleware = localeDetection({
  locales: ["en", "id"],
  defaultLocale: "en",
  // strategy: "all",
  // cookieName: "locale",
  // redirectStatus: 302,
});
```

If you need custom behavior, compose `negotiateLocale()` and `localePath()` manually; the helper
keeps detection explicit and configurable.

## Metadata and alternate links

Each locale route gets `<html lang>`/`dir`, locale-aware loader cache keys, and `<link
rel="alternate" hreflang>` entries for every configured locale plus `x-default` (see
`packages/ssr/test/i18n.test.ts`). Per-route metadata (title/description/canonical/OG) is read from
the page module; use the active `locale` in loader data/content and set a locale-specific canonical
where needed.

## Limitations (honest)

- ICU support is a subset: no custom tag/style formatters, offsets, or spellout.
- Catalogs are app-provided (JSON/data store) — the framework does not load files for you.
- One route per locale (linear in the number of locales); per-route localization is not supported.
- `hreflang` uses the page's logical path; dynamic routes follow the currently requested params.
- `localeDetection` is a redirect helper, not a CDN/Vary strategy; cache rules remain app-owned.
